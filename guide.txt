# Frontend Guide: Creating Orders and Using the Payment API (PhonePe Standard Checkout)

This guide explains how the frontend should:
- Build a cart and compute pricing (including shipping) client-side
- Create an order via our API
- Initiate a PhonePe hosted checkout payment
- Handle the result and show status to the user (and let the server send notifications)

All amounts are stored and exchanged in paise (₹1 = 100 paise) on the server.

## Overview

1. Build the cart in the frontend and compute:
   - Subtotal (sum of line items)
   - Shipping (computed client-side; see examples below)
   - Discount (optional)
   - Tax (optional)
2. Create order: POST `/api/orders`
3. Initiate payment: POST `/api/payments/phonepe/initiate`
4. Redirect the user to the `providerResponse.redirectUrl`
5. After user completes/cancels, PhonePe redirects to `/checkout/result?mtid=...`
6. The result page MUST poll `/api/payments/phonepe/status?merchantTransactionId=...` until it sees `COMPLETED` or a final failure. Notifications (WhatsApp/SMS/Email) are triggered on the server ONLY after status becomes `COMPLETED`.

### Critical: Implement the Result Page (Polling)

You must implement the two redirect pages so they actually call our status API. Simply creating two static pages is not enough. The page needs to read `mtid` from the URL and poll the API until completion.

Vanilla HTML/JS example:

```html
<!doctype html>
<html>
  <head><meta charset="utf-8"><title>Payment Result</title></head>
  <body>
    <h1>Processing payment…</h1>
    <div id="msg"></div>
    <script>
      const p = new URLSearchParams(location.search)
      const mtid = p.get('mtid')
      const msg = document.getElementById('msg')
      if (!mtid) {
        msg.textContent = 'Missing mtid in URL.'
      } else {
        async function poll() {
          try {
            const res = await fetch(`/api/payments/phonepe/status?merchantTransactionId=${encodeURIComponent(mtid)}`, { cache: 'no-store' })
            const json = await res.json()
            if (!res.ok) throw new Error(json.error || `HTTP ${res.status}`)
            const code = String(json.code || '')
            if (code === 'COMPLETED') {
              msg.textContent = 'Payment confirmed! Your order is placed.'
            } else if (code === 'PENDING' || code === 'CREATED') {
              setTimeout(poll, 2000)
            } else {
              msg.textContent = 'Payment failed or cancelled. Please try again.'
            }
          } catch (e) {
            msg.textContent = e.message || 'Unexpected error'
          }
        }
        poll()
      }
    </script>
  </body>
  </html>
```

Next.js example (we already ship this under `app/checkout/result/page.tsx`):

```tsx
// app/checkout/result/page.tsx
"use client"
import { useEffect, useMemo, useState } from 'react'
export default function CheckoutResultPage(){
  const [status, setStatus] = useState<'idle'|'pending'|'success'|'failed'|'error'>('idle')
  const [message, setMessage] = useState('')
  const mtid = useMemo(() => {
    if (typeof window === 'undefined') return ''
    return new URLSearchParams(window.location.search).get('mtid') || ''
  }, [])
  useEffect(() => {
    if (!mtid) return
    setStatus('pending')
    let cancelled = false
    async function poll(){
      try{
        const res = await fetch(`/api/payments/phonepe/status?merchantTransactionId=${encodeURIComponent(mtid)}`, { cache: 'no-store' })
        const json = await res.json()
        if (!res.ok) throw new Error(json?.error || `HTTP ${res.status}`)
        const code = String(json?.code || '')
        if (code === 'COMPLETED') { setStatus('success'); setMessage('Payment confirmed. Your order has been placed.'); return }
        if (code === 'PENDING' || code === 'CREATED') { if (!cancelled) setTimeout(poll, 2000) }
        else { setStatus('failed'); setMessage('Payment failed or cancelled. Please try again.') }
      } catch(e:any){ if (!cancelled){ setStatus('error'); setMessage(e?.message || 'Unexpected error') } }
    }
    poll(); return () => { cancelled = true }
  }, [mtid])
  return <div>{message || (status==='pending'?'Processing payment…':'')}</div>
}
```

Once the status API returns `COMPLETED`, our server updates the database (`orders.status = 'paid'`) and triggers notifications. You do NOT need to send notifications from the frontend.

## Going Live

- Switch `PHONEPE_BASE_URL` to `https://api.phonepe.com` and use live OAuth credentials.
- Ensure `PUBLIC_BASE_URL` points to your production domain.
- Whitelist your redirect/cancel URLs in PhonePe if required.

### Redirect URL domain rules

- We build redirect/cancel URLs from `PUBLIC_BASE_URL` and strip `www.`. Use `https://tintucuts.com` or, if you host under a path, `https://tintucuts.com/admin`.
- Ensure those pages exist and implement the polling logic above.

## Backend variant: Python SDK service

We can optionally use an external Python FastAPI service (PhonePe Python SDK) for payment initiation and status. This is transparent to the frontend.

- Backend env vars:
  - `PY_PHONEPE` = URL of the Python service (e.g., `https://your-python-app.vercel.app`)
  - `PY_TOKEN` = shared bearer token; Node calls the Python service with `Authorization: Bearer <PY_TOKEN>`
- Frontend: unchanged. Keep calling our Next.js APIs (`/api/orders`, `/api/payments/phonepe/initiate`, `/api/payments/phonepe/status`).
